## Root causes and solutions

### Errors

**E1. Release Preflight: `npm refused the OIDC package exchange (404)` (run 37987850798, attempt 1).**
This is the preflight added in PR 30 doing its job: it calls npm's OIDC package exchange, the endpoint `npm publish` uses, before anything is versioned. The npm trusted publisher still named `konard/disk-space-saviour` (see `dev/log/issues/29/pulls/30`), so the exchange was refused and the release stopped with an explicit message instead of failing at publish time. Fixing it takes a setting on npmjs.com, not a code change. A maintainer made it, and the re-run at 22:00 printed `PASS: npm OIDC package exchange verified (returned token discarded)` and published `0.15.1` (`ci-logs/run-37987850798-attempt2-*.log`). No code change is needed.

**E2. "Check for Changesets" and "Dry-run release versioning (PR only)" fail on this branch with `No unreleased changesets found` (run 38000089291).**
The release of `0.15.1` consumed the previous changeset, so this branch had none. Fixed by `.changeset/ci-issue-31.md`. Both checks are working as intended.

**E3. Broken Link Checker fails on this branch (run 38000089234): 5 errors in `upstream/hive-mind-CI-CD-BEST-PRACTICES.md`.**
The copied document links to its siblings (`CI-CD-BEST-PRACTICES.zh.md`, `CONTRIBUTING.md`, …), which exist only upstream. lychee checks `md,html`, so the snapshot is now stored as `.txt`, the same way issue 29 stored its template snapshots.

### Hazards found while fixing F1

- `deno test --parallel` runs files in workers that share one working directory, so no test may call `process.chdir`. The commit-message test passes `cwd` instead.
- `deno test` with `nodeModulesDir: "auto"` rewrites `node_modules` (it installed prettier 3.9.9 over the npm tree) and can touch `deno.lock`. CI legs are separate jobs, so only local runs need `git checkout deno.lock && npm ci --ignore-scripts` afterwards (`docs/CONTRIBUTING.md`).
- A fixture started from a shell is outside Deno's node-compat argument translation, so it must run through `deno run -A` (without it the first `process.env` read fails). The CommonJS gh fixture was renamed from `fake-gh.js` to `fake-gh.cjs` for the same run (`tests/create-github-release.test.js`, commit `6560ed6`).
- Sequential `deno test -A` took about 152s locally; `--parallel` took 40–50s (49s in the last full run). The budget is 200s.
- A bare `bun test` collects every file named like a test anywhere in the tree, while Node runs `tests/*.test.js` and Deno `tests/`. An experiment named `*.test.mjs` made Bun report 1111 tests with 2 skips against Node's 1108. It is now `experiments/test-anywhere-describe-skip.repro.mjs`, and `tests/visible-skips.test.js` fails if a test-named file appears outside `tests/`.

## Best-practice checklist (hive-mind CI-CD-BEST-PRACTICES)

- **No silent success:** a test that cannot run is reported as skipped with its reason, never as passed or absent (F1). A guard test keeps new gates out.
- **Same coverage on every runtime:** Deno runs the fixtures with `-A`, so the three runtimes differ only by the skips each summary lists.
- **Tools see their real configuration:** jscpd fails a test on unknown keys (F4); zizmor runs online in both passes (F2).
- **Triggers cover every input a job reads** (F3).
- **Warnings are actionable or gone:** W1–W3 are fixed. Every other warning is listed above with the reason it stays.
- **Fail closed before release:** the preflight stopped the release on E1 with the cause, before anything was versioned.
- **Bounded jobs:** the Deno step has a 200s budget with a warning at 70%, like every other step (`docs/CI-TIMEOUT-BUDGETS.md`).

## Existing tools considered

- **test-anywhere** (kept): `it.skip` is the only skip all three runtimes report, so `itUnless` builds on it. A skip reason upstream (test-anywhere#149) would make the name suffix unnecessary.
- **Node's `t.skip(reason)`, Bun's `test.skipIf`, Deno's `ignore`:** each prints a skip natively, but none of them works on all three runtimes, which is why the suite uses test-anywhere.
- **jscpd 5** (kept): `mode: weak` is its documented spelling of comment skipping.
- **zizmor 1.30.1** (kept): online mode needs only `GH_TOKEN`, which the job already has.
- **npm `allowScripts`** (adopted): approving scripts by name keeps the review in the lockfile's package.json, where npm already looks.
