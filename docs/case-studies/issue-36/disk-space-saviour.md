## Root cause

Static defaults did not cover several regenerable toolchain caches and ignored environment/tool configuration. nvm and SDKMAN commands are shell functions and need their initialization files. Semver baselines are independent regenerable artifacts, whereas gem archives must be selected as files to preserve installed gems.

## Existing components and online facts

[Go module reference](https://go.dev/ref/mod), [npm configuration](https://docs.npmjs.com/cli/v8/using-npm/config/), and [pip caching](https://pip.pypa.io/en/stable/topics/caching/) support resolving configured locations. [Perlbrew](https://metacpan.org/pod/perlbrew), [nvm source](https://github.com/nvm-sh/nvm/blob/master/nvm.sh), [SDKMAN usage](https://sdkman.io/usage/), and [SDKMAN flush source](https://github.com/sdkman/sdkman-cli/blob/master/src/main/bash/sdkman-flush.sh) establish native command constraints. Current flush source handles tmp/temp, metadata and version, not archives; the issue’s suggested `sdk flush archives` is not used. [cargo-semver-checks](https://github.com/obi1kenobi/cargo-semver-checks) documents the tool generating the baseline builds. Native tools and file patterns solve this without a new cache library.
